# Flow / WMS / Device 逐步实施计划与代码基线

> 核查基准：`86ff9cbacc8fef9baa56d17430089c35aaf7d1a5`（2026-11-09）。这是后续逐项实施的主计划，无时间排期。状态是静态代码判断，不等于运行环境验收。每做完一项，记录测试与场景结果后再改为“已验收”。
>
> 本轮范围：Flow、WMS、Device、WMS/Device API，以及尚无实现的统一资源契约。**Transport 模块、ES 权限查询、审计均不在本轮任务内**；不因本计划修改其代码或列其交付任务。系统既有租户/功能权限保持现状。对外任务关联和设备时间只处理与三模块闭环直接相关的最小能力，外部开放接口暂缓。

## 判定口径

- **已有待验**：接口和实现存在，尚缺完整场景或运行环境验收。优先核验，失败再修复。
- **局部已有**：有部分实现，但指定语义或完整链路缺失。
- **缺失**：未发现对应契约、实现或迁移脚本。先设计最小契约再编码。
- 证据均指向当前仓库的类或脚本；仅按文件存在不能证明已在真实数据库部署。

## 本轮执行任务表（按依赖顺序）

本轮只处理“记录可追踪、设备不会被 Flow 擅自重发、样本和物料闭环可验证”。已有实现先测再修；不为将来可能出现的业务场景预建完整模型。

|---|---|---|---|---|---|

## 删减、合并与后置

| 原编号 | 处理 | 依据与重新进入条件 |
|---|---|---|
| F05 原“重试分级” | **删除方案，保留安全修复** | Flow 不应独自决定设备是否重做物理动作；只封禁现有自动重发入口 |
| D03 + F03 | **合并** | 两者验证同一条“设备回报→Flow 信号结算”链；不分别建设大而全的测试工程 |
| W01 + W03、W04 + W05 | **合并验收** | 对应代码及测试已存在；先验证跨接口语义，避免按旧 TODO 重写 |
| W02、W06、X01 | **后置** | 衍生登记、实物化和八态已有基础；多父合样、完整生命周期范式与自动联动需明确真实业务流程后再补。最小闭环只验证实际用到的状态 |
| F04 | **后置** | 发布期跨模块全量静态检查会扩大依赖面；先用 X02 找到真实反复出错的配置，再只前移那些可静态判定的规则 |
| D04、D05 | **后置** | 设备时间校准和 schema 版本有长期价值，但不是当前三模块最小闭环的前置；有实际设备时间字段与结果重算需求时启动 |
| C01 | **后置** | 外部任务关联属于接入 LIMS/MES 的阶段；内部闭环先用 `executionId` 与现有来源字段关联 |
| R01、R02、R03 | **后置，其中 R03 不单列本轮任务** | WMS 已有物料预留，Device 有设备状态；尚未验证跨设备/库位的真实争用。出现跨域共享占用与分配需求后，再联合设计资源模型和调度输入，先落租约，最后考虑分配决策 |
