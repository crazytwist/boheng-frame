# 样本域分析（Sample）

> 模块：`boheng-module-wms`（`sample` 包）+ `boheng-module-wms-api`（契约）
> 定位：样本是「**业务对象**」，独立于实物。它回答——**这次送检/实验的业务样本是什么、它的谱系（血缘）、它走到哪一步了**。

---

## 一、三层模型

样本夹在「物质」与「实物」之间，是三层模型的中间层：

```
wms_content_def        物质定义（「是什么物质」）
        ↓
wms_sample_info        样本主表（谱系 / 状态 / 实验参数 / 流程关联）← 本域
        ↓
wms_material_instance  实物实例（sample_id 关联样本）
```

**关键区别**：样本可以**提前登记**（还没实物），实例化时才把 `sample_id` 挂到 `material_instance` 上。一个样本可对应多个实例（分装 1:N）。

---

## 二、样本主表（wms_sample_info）

### 2.1 谱系五件套（血缘）

| 字段 | 含义 |
|---|---|
| `sampleId` | 样本业务编号（条码/二维码，租户内唯一） |
| `parentSampleId` | 父样本编号（NULL = 原始样本） |
| `rootSampleId` | 根样本编号（原始 = 自身，查整棵谱系树） |
| `generation` | 谱系代数（原始 = 0，每拆分/合并一次 +1） |
| `deriveType` | 衍生类型：ORIGINAL / SPLIT / ALIQUOT / MERGE / ADD_REAGENT |

谱系冗余由 `createSample` **自动计算**：原始样本 `root=自身、generation=0、deriveType=ORIGINAL`；衍生样本沿父累加 `generation+1`、`root` 沿父。

### 2.2 其它关键字段

- `sampleType`（字典 wms_sample_type：WATER/BLOOD/SOIL/…）
- `contentDefId / contentDefCode`：样本是什么物质
- `containerTypeCode`：期望容器类型
- `initialVolUl`：登记承诺量（不再变更；当前量在实例 `current_vol_ul`）
- `experimentParams`（JSON）：流程步骤执行时读，如 `{"targetPh":7.2,"volumeUl":500}`
- `status`：八态（见下）
- `currentExecutionId / currentNodeId`：当前在哪个流程的哪个节点
- `batchNo / orderNo / priority / source / externalId / collectedAt / receivedAt / expireTime`

## 三、八态状态机

### 3.1 八态含义

| 状态 | 含义 |
|---|---|
| REGISTERED | 已登记（建档，未装载实物） |
| LOADED | 已装载（实例化挂到 material_instance） |
| IN_PROCESS | 处理中（正在流程步骤执行） |
| SPLIT | 已拆分（母样本拆分，子样本继续） |
| COMPLETED | 已完成（走完流程） |
| ARCHIVED | 已归档 |
| REJECTED | 不合格 |
| LOST | 丢失 |

生命周期主线：`REGISTERED → LOADED → IN_PROCESS → COMPLETED → ARCHIVED`
分支：`IN_PROCESS` 派生 `SPLIT` / `REJECTED` / `LOST`。

### 3.2 流转表（当前实现，待业务确认）

代码里 `SampleInfoServiceImpl.STATUS_TRANSITIONS`：

```
REGISTERED → LOADED / REJECTED / LOST
LOADED     → IN_PROCESS / REJECTED / LOST
IN_PROCESS → COMPLETED / SPLIT / REJECTED / LOST
SPLIT      → COMPLETED
COMPLETED  → ARCHIVED
ARCHIVED   → （终态）
REJECTED   → （终态）
LOST       → （终态）
```

- **同态幂等放行**：`from == to` 时允许（用于只更新流程关联字段）。
- **空目标状态**：`updateSampleStatus` 传空 status 只更新 `executionId/nodeId`，不做流转（已修复「空会把状态 set 成 null」的隐患）。

> ⚠️ **待业务确认点**（我按 `SampleStatusEnum` 注释推断的保守版，需你拍板）：
> 1. `SPLIT` 是流向 `COMPLETED`（母样本拆完算完成），还是 `SPLIT` 本身就是终态不再流转？
> 2. `COMPLETED → REJECTED`：检测完成后结果复核判「不合格」是常见场景，当前表**不允许**，是否需要补这条回退？
> 3. 是否允许 `REGISTERED → IN_PROCESS` 跳过 `LOADED`（纯虚拟/电子样本不装载实物）？
> 4. `REJECTED` 能否重新处理回 `IN_PROCESS`？

## 四、与实例状态的正交（最重要的一张表）

样本状态与实例状态**是两个独立维度，互不联动**：

| 维度 | 样本八态 | 实例六态 |
|---|---|---|
| 驱动者 | **流程引擎** | **物理操作** |
| 状态 | REGISTERED/LOADED/IN_PROCESS/SPLIT/COMPLETED/ARCHIVED/REJECTED/LOST | AVAILABLE/RESERVED/IN_USE/USED/EXPIRED/DISCARDED |
| 绑定 | `sample_id` 挂在实例上 | `root_slot_id` 表示落位 |

**推论**：
- 「生成实例」（分装）**不联动**样本状态——样本登记后仍是 REGISTERED，装载才由流程显式 `updateStatus` 驱动。
- 「独立走流程」的载体是**子样本**（拆分），不是实例。

---

## 五、分装 vs 拆分（两种都要）

| 场景 | 机制 | 关系 |
|---|---|---|
| 分装（生成实例） | 1 个样本 → N 个实例，共享 `sample_id` | 样本 1:N 实例 |
| 拆分 | 母样本 → 子样本（谱系自动）→ 各自实例化 | 样本谱系树 |

拆分闭环：`母样本 → 列表「拆分」→ 登记子样本（root 沿父、generation+1、deriveType=SPLIT）→ 子样本再「生成实例」→ 独立走流程`。

## 六、契约层（SampleApi）

`boheng-module-wms-api` 对外暴露，供 flow 调用：

| 方法 | 用途 |
|---|---|
| `registerSample(SampleRegisterReqDTO)` | 登记样本（提前建档），返回 sampleId |
| `updateStatus(sampleId, status, executionId, nodeId)` | 状态流转（节点驱动） |
| `getSample(sampleId)` | 读样本摘要（含实验参数） |
| `getSamples(sampleIds)` | 批量读样本摘要 |

`SampleRegisterReqDTO` 含 `parentSampleId` + `deriveType`（衍生样本登记必填 deriveType）。

---

## 七、已修复的漏洞（本轮）

1. **删除保护**：`deleteSample` 前校验实例引用，已生成实例则拒绝（`SAMPLE_HAS_INSTANCES`），杜绝 sample_id 悬空。
2. **状态机约束**：`updateSampleStatus` 走流转表校验（`SAMPLE_STATUS_TRANSITION_INVALID`）。
3. **谱系一致性**：原始样本强制 ORIGINAL、衍生样本必须落合法衍生类型（`SAMPLE_DERIVE_TYPE_INVALID`）；更新时 `deriveType` 不接受前端覆盖。

---

## 八、待办 / 缺口

- **状态驱动链路**：`updateStatus` 入口 + 状态机已就位，但「谁在何时驱动 REGISTERED→LOADED」属业务流程编排，框架不硬编码（因已定「生成实例不联动状态」），需流程动作 Bean 显式调用。
- 实例表暂缺 `batch_no/lot_no/received_at/opened_at/expired_at`（v1.4 原设计有，当前简化）。
