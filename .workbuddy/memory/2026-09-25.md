## 空间域修订 v1.1（用户复盘 zone / slot 后调整）

### 用户提出的两点意见（均已落地）
1. zone 需要能配置「当前使用的物料类型」（可用 JSON 或字典指定）
2. slot 要回归槽位本质：不保留继承自 zone 的字段（表高频变动）；状态要区分可用态与使用态；被占用时需记录占用物料

### 问题诊断（根因）
- `slot.temp_min/temp_max` 注释写「为空则继承区域」→ 继承型冗余字段，槽位高频变动下与 zone 双写必然不一致
- `slot_status` 同时含 EMPTY/OCCUPIED/LOCKED/DISABLED/CHECKING → `DISABLED` 与 `status`(0启用/1停用) 语义重叠，两个维度挤在一个字段
- slot 只有 `lock_source/lock_ref_id`（谁锁的），没有占用方
- zone 无任何物料类型约束入口，入库时无校验依据

### 决策链（用户逐步确认）
1. 物料类型存储形态：先选「逗号分隔 + 字典驱动」→ **用户反问是否该独立成表** → 给出对比（关系 vs 属性、反查索引、扩展属性）后改选 **独立关联表**
2. 关联表字段：`zone_code` + `material_type` + **`sort_no`（优先级）+ `max_qty`（数量上限）**，预留扩展
3. 子区域未配置时**沿 parent_zone_code 继承**
4. zone 表**不新增** material_types 字段（关系全部落关联表）
5. slot 只砍温区字段（位置/容量/设备映射/unique_batch 全保留）
6. 占用信息**只记物料**（`occupied_material_id` + `occupied_material_code` + `occupied_time`）
