## 数据平台技术方案（对外项目，非 boheng-frame 本体）
- 场景：数据来自各业务系统（内部 LIMS/ERP/MES、兄弟项目组、外部合作方、仪器文件），统一处理后喂给 AI
- 定调：**不上互联网大数据全家桶**，走轻湖仓 + 对象存储 + 向量库；StarRocks/Paimon/MinIO/SeaTunnel/Debezium/DolphinScheduler/Milvus
- 关键判断：AI 消费必须拆三条路径（语义层问数 / 向量 RAG / MCP 直连实时接口），混在一起设计必翻车
- 采集按权限分四级通道：L1 只读库视图 > L2 API > L3 文件落盘 > L4 RPA 兜底；跨项目只靠技术不够，要数据源台账 + 数据契约
- 用户确认：内部+外部源都有，一起设计；暂无源清单只有预估 → 架构做成可扩展（连接器插件 + 台账驱动）；默认不跨网段/机房，单机房内网

## Archify 使用踩坑（重要）
- 技能装在 `~/.workbuddy/skills/archify`，CLI `node ~/.workbuddy/skills/archify/bin/archify.mjs`
- ★ 必须先 `unset NODE_OPTIONS`：注入的 node-language-shim 会拦截 safe-delete，导致 `finalize/receipt-publication` 失败（removal-quarantine-cleanup-failed）
- ★ Chrome 在沙箱内起不来（sandbox initialization failed: Operation not permitted）→ 用包装脚本 `ARCHIFY_CHROME=/tmp/archify-chrome.sh`，内容为 exec Chrome 加 `--no-sandbox --disable-gpu`
- ★ 重复 finalize 同一输出路径会报 `viewer/evidence-path-conflict` → 加 `--out-dir <dir>/review-N`
- 架构图列宽经验：viewBox 超 1500 时节点文字投影会掉到 6px 边缘；6 列（列宽 160、列距 90）在 1440 视口约 7.2px，可读
- 产物：`output/data-platform-architecture.html`、`output/data-platform-roadmap.html`
