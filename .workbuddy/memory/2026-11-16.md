## archify 踩坑（本次新增）

- **`meta.views` 不会被渲染**：architecture schema 的 component 只有
  `id/type/label/sublabel/tag/icon/brand/sources/row/col/pos/size`，没有视图机制；
  写了 `meta.views` 不会报错但产物 HTML 里 0 匹配。
- **`tag` 是「细节层」文本**（`data-detail="fine"`，font-size 7），默认缩放下几乎看不见。
  要在图上标状态，必须写进 `sublabel` 或 `label`。
- 连线路由对**同列 4 行跨度**（440→40）会算出 y=-8 越界，报 `layout/route-out-of-bounds`；
  3 行跨度（340→40）可以正常走。
- 一个节点 3 条出边会让邻居标签落进共享走廓，报
  `composition/label-route-clearance`；去掉冗余边标签（如 MinIO 已有 sublabel 时删「原始备份」）即可解。
- `/tmp/archify-chrome.sh` 会被系统清理，跨天重跑要先重建。

### 开源对标调研（11-19）
结论：**没有和我们那张图等价的开源项目**。「数据+文件驱动」这个特征把开源世界切成两半——研究数据管理（openBIS / Dataverse / CKAN，管数据集与文件、强元数据、弱分析）和现代数据栈（havn / OpenMetadata / Cube / RAGFlow，强分析、不管文件）。我们的图跨了两半，所以只能组合。
最值得照抄架构的是 **openBIS**（ETH，Apache-2.0）：Space/Project/Experiment/Object/Dataset 五层模型 + Inventory 物料设备台账 + 审计，场景和自动化实验室几乎重合。**关键提醒：我们的图缺「数据归属模型」——MinIO 里一个文件属于哪个样本/实验/批次，图上没有表达。**
可直接替掉自研的三块（均 Apache-2.0）：OpenMetadata（资产目录/血缘/质量/权限，3-4 容器）、Cube Core（语义层+预聚合+行级权限+SQL/REST/GraphQL/MCP）、RAGFlow（DeepDoc 版面分析/OCR/表格识别+切片+检索，93k star）。
havn（DuckDB 单文件数仓，landing/bronze/silver/gold）架构清晰但规模撑不住 12TB，只作参照。
