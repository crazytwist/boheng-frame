设备域架构 v4 · 参考 librax 之后的修订

参考对象：内部既往系统 /Volumes/External_1TB/Projects/librax/（已跑通的同类系统，非纸面设计）。
v4 相对 v3 的修订原则：借它的三条运行时不变量（幂等作用域 / 状态与等待原因分离 / 超时归约）， 反着做它的两处 bug（非原子抢占、执行态只放缓存），保留我们比它强的地方（多租户 / 配置记录分离 / 数据三层）。

图 1 · 分层总览：四个域 + 一条接缝

调度域只给「条件」，不给设备编码；设备域内部五步全走同一条路径；Transport 收缩为两种协议加一个仿真。

图 2 · 三态调用：四层决策与统一出口

三种调用方式不是三个接口，而是同一个命令的两个正交维度。四层决策后者覆盖前者，出口只有一个。

图 3 · 命令生命周期与三类超时

加粗高亮的三步是我们相对它改强的地方：先落事实再抢设备、CAS 必须原子、判失败前先对账。

图 4 · 表结构归位与字段级改动

改动只落在两张表上，其余零改动；新增一张解析规则表。

相对 v3 改强的五处

升级内容与理由
新增先落事实再抢设备 状态从 CREATED 起：先把命令事实入库，再去抢设备。抢不到也留一条「没排上」的事实， 可观测、可统计资源缺口、崩溃可恢复。原系统是选设备与抢占写在一次调用里，失败了无痕。 推论：device_id / device_code 必须改可空。
新增状态 × 等待原因正交 status 只表达设备侧事实，waiting_for 表达「在等什么」： SLOT_AVAILABLE（等空闲设备）/ DEVICE_CALLBACK / POLL_TICK / MANUAL_APPROVE / EXTERNAL_EVENT。三类超时各自挂在对应等待原因上。
新增判失败前先对账 超时不是直接落 TIMED_OUT，而是先追加一次轮询确认真实状态再判。 与「回调超时先降级轮询」同源。原系统把超时直接归约成失败，存在设备已跑完却被判失败的误报。
吸收三键分工的幂等 uk_command_no（对外）/ uk_idempotent（传输重投）/ uk_business（业务执行事实，含 attempt）。 只有单列幂等键时，重试会被拦成「返回原命令」→ 调度域永远看不到第 2 次执行，重试等于没重试。 手工触发时 business_exec_id/node_id 为空，MySQL 唯一索引 NULL 不参与去重， 正好实现「手工命令不做业务幂等」。
吸收回调鉴权与时间戳分工 callback_token_hash 只存 SHA-256 摘要，异步执行签发、回调校验。 没有它，任何人 POST 就能灌伪造测量数据。 时间戳分工：acquired_at → sent_at = 排队多久，sent_at → 结束 = 设备跑多久； 缺第一个点则分不清「选不到空闲设备」还是「设备太慢」。

保留：我们比它强、不许退步的地方

项说明
保留多租户每张表带 tenant_id，唯一键一律含租户。
保留配置与记录分离动作/属性/参数集是配置（可增删改）；命令/原始数据/测量/分析是记录（只增不改，无删除入口）。
保留能力用独立表动作、属性各有独立表与错误码段；不退回「型号表塞一个大 JSON」。
保留数据三层L0 不可变 → L1 可重算 → L2 带 rule_version 可重判；上下文在摄入时挂上，不事后猜。
保留锁语义锁四字段（持有方/类型/取得时间/过期时间）+ 能过期；抢占用原子 UPDATE，不用先查后改。

不采纳

  • 否无 tenant_id 的单租户设计。
  • 否平台直连 TCP / 串口 / SDK —— 仍交由接入层翻译，平台只认 HTTP + MQTT。
  • 否执行态只放缓存 —— 缓存过期即事实丢失，状态必须以库表为准。
  • 否先建字段后补实现 —— 「表里有、代码从没读过」是本项目已发现的最大坑。
  • 否解析脚本存 Groovy/JS —— 代码注入面，一期只开 JSON / REGEX 两种解析类型。
  • 否解析与标准化焊在一处 —— 单位换算与有效值范围属 L1 层，不放进解析规则表。
